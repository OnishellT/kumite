# Code Standards

This live document contains project-specific coding rules. When the project has no explicit standards yet, default to strict, boring, maintainable code.

## General Standards

- Prefer the existing project patterns over new abstractions.
- Keep changes scoped to the task and plan.
- Add tests for changed behavior.
- Avoid broad refactors unless the plan explicitly calls for them.
- Keep dependencies minimal and justified.
